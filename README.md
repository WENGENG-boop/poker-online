# 在线牌局 · 跑得快 / 斗地主

前端：React 19 + TypeScript + Vite。后端：Node.js（内置 http + ws + 内置 SQLite）。
游戏规则、房间逻辑、聊天审核这些代码前后端共用，后端是权威：手牌、出牌合法性、审核全部在服务器上判定。

## 运行

**在线模式（真实联机，不同设备可以一起玩）**
```bash
npm install
npm run server        # 后端，端口 8787（修改代码会自动重启）
npm run dev:online    # 另开一个终端：前端，地址 http://localhost:5173，自动把接口转发到后端
```
首次启动后端时会在终端打印一次随机生成的后台密码，也可以用环境变量 `ADMIN_PASSWORD` 自己指定。
想让同一局域网里的手机也能加入：手机浏览器访问 `http://<电脑的局域网 IP>:5173`。

**本地模拟模式（不需要后端）**
```bash
npm run dev           # 同一浏览器开多个标签页，用邀请码模拟多人
```

**测试**：`npm test`。包括规则、引擎、AI、聊天审核，以及启动真实服务器的端到端测试。

## 部署上线
**方式一：Docker（推荐）**
```bash
docker build -t poker .
docker run -d -p 8787:8787 -v poker-data:/app/data -e ADMIN_PASSWORD=你的后台密码 poker
```

**方式二：直接用 Node.js 运行（需要 22.13 或更高版本）**
```bash
npm ci
npm run build:online && npm run build:server
ADMIN_PASSWORD=你的后台密码 npm start
```

一个进程同时提供前端页面、`/api` 接口、`/ws` 实时对局和 `/admin` 后台，数据保存在 `data/poker.db`。
有了域名和 HTTPS 之后，前面加一层 Nginx 或 Caddy 反向代理即可。注意要转发 WebSocket，并设置 `TRUST_PROXY=1`。

| 环境变量 | 说明 |
|---|---|
| `PORT` | 端口，默认 8787 |
| `ADMIN_PASSWORD` | 后台密码；不设置时首次启动自动生成并打印一次 |
| `SESSION_SECRET` | 玩家令牌签名密钥；不设置时自动生成并保存到数据库 |
| `DATA_DIR` | 数据目录，默认 `./data` |
| `TRUST_PROXY` | 部署在反向代理之后时设为 `1`，用于获取真实 IP（限流要用） |
| `CORS_ORIGIN` | 前后端部署在不同域名时，填前端的域名 |
| `MAX_ROOMS` | 最多同时存在的房间数，默认 500 |

### 后端做了什么
- **权威服务器**：每位玩家只会收到自己的手牌，出牌合法性和名次都由服务器判定。
- **安全**：
  - 玩家令牌用 HMAC 签名，伪造令牌连不上；
  - 所有客户端消息都会做类型和范围校验，非法消息直接丢弃；
  - 有限流：创建房间、加入房间、WebSocket 消息都有频率限制；
  - 请求体大小有限制。
- **审核**：昵称和聊天都在服务器端审核，被拦截的内容写入数据库，后台可以查看。
- **后台**：密码由服务器校验，连续输错 5 次锁定 60 秒，登录会话 2 小时后过期。
- **稳定性**：
  - 房间状态持久化，服务器重启后自动恢复，玩家用原来的令牌就能重连；
  - 断线后自动重连；
  - 房主离线 30 秒会自动把房主移交给其他在线玩家；
  - 无人在线的房间 30 分钟后自动清理；
  - 每局完整记录存入 SQLite，后台可以复盘。

## 玩法
不计积分，只排名次。
- **跑得快**：3～8 人，支持多副牌。最先出完的是赢家，其余玩家继续打，依次决出第二名、第三名……出完牌后如果没人能压，由他的下家接风领出。
- **斗地主**：3 人 1 副，或 4 人 2 副。玩家轮流“叫地主 / 抢地主”，每人一次，最后叫或抢的人当地主，拿走底牌（公开）后先出牌。地主或任一农民先出完，所在一方获胜。另外支持四带二。
- **AI**：规则型 AI，在服务器上运行，不需要任何配置或 API Key。房主可以在房间里选难度：简单、普通、困难。

## 快捷聊天与内容审核
- 可以发预设短语、预设表情，以及 6 字以内的短文字。房主可以设为“仅短语和表情”或者关闭聊天。
- 审核在服务器端执行（`src/net/moderation.ts`）：
  - 先规范化文字（全角转半角、去空格和符号），防止变体绕过；
  - 再用敏感词库拦截辱骂、拼音缩写、色情、暴力、歧视、广告引流和联系方式；
  - 表情只认预设列表；
  - 发言有频率限制，5 分钟内违规 3 次会被禁言 2 分钟。
- 昵称也会审核。玩家可以屏蔽某个人的消息。被拦截的内容只会出现在后台。
- **注意**：敏感词库只能拦截常见说法。正式上线建议同时接入云内容安全服务（阿里云、腾讯云等），在 `checkText` 里追加调用即可。

## 后台管理（仅限 `/admin`）
- 前台页面没有任何指向后台的入口。访问 `/admin` 并输入密码后，才能看到：
  - 房间监控：在线状态、延迟、手牌数、最近聊天、拦截记录；
  - 历史记录：统计数据、按玩法筛选、按房间号或玩家名搜索、名次明细、逐手复盘、导出 JSON、删除。
- 在线模式下，密码由服务器校验（环境变量 `ADMIN_PASSWORD`），历史记录保存在服务器数据库里。
- 本地模拟模式只用于开发演示，密码在前端校验（默认 `admin888`，可用 `npm run admin-hash` 修改），不要用于正式环境。

## 目录
| 路径 | 说明 |
|---|---|
| `server/` | 后端：`app.ts` 路由与 WebSocket、`rooms.ts` 房间管理、`db.ts` SQLite、`auth.ts` 鉴权限流、`validate.ts` 消息校验 |
| `src/game/` | 规则、引擎、AI（前后端共用） |
| `src/net/roomServer.ts` | 权威房间逻辑（前后端共用） |
| `src/net/moderation.ts` | 聊天和昵称审核（前后端共用） |
| `src/net/remote.ts` / `adminApi.ts` | 前端连接后端的客户端 |
| `src/net/connection.ts` | 本地模拟模式（BroadcastChannel） |
| `src/pages/`, `src/components/` | 页面与组件 |
